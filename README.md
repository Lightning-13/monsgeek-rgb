# MonsGeek RGB

A Python library and protocol documentation for controlling the RGB lighting on the **MonsGeek FUN60 Pro** without using the official MonsGeek software.

This project is the result of a complete reverse engineering effort of the keyboard's USB HID RGB protocol. It communicates directly with the keyboard using `hidapi`, bypassing the official application, `iot_driver.exe`, and its gRPC communication layer.

---

## Features

* ✅ Direct USB HID communication
* ✅ No dependency on the official MonsGeek software
* ✅ Automatic detection of wired and 2.4 GHz modes
* ✅ Static RGB lighting
* ✅ Persistent per-key RGB layouts (Custom Layer)
* ✅ Brightness control
* ✅ Reverse-engineered protocol documentation

## Quick Example

```python
from fun60_controller import FUN60Controller

with FUN60Controller() as keyboard:
    keyboard.set_all(0, 255, 0)
```

This writes a persistent green layout to the keyboard's Custom Layer.

---

## How It Works

The keyboard exposes a vendor-specific USB HID interface for RGB control.

Instead of communicating with the official software, this project sends HID Feature Reports directly to Interface 2. RGB data is written into the keyboard's internal framebuffer and committed to the onboard Custom Layer using the same protocol employed by the official application.

## Limitations

The protocol currently supports persistent Custom Layer writes only.

During this investigation, no general-purpose RAM-based RGB streaming protocol was identified. The official MonsGeek software also commits changes to flash rather than providing live per-key RGB preview.

This means the library is well suited for:

* Static layouts
* Per-key color profiles
* Configuration utilities

It is **not** suitable for high-frame-rate animations such as those typically generated by SignalRGB or OpenRGB unless a previously undocumented streaming protocol is discovered.
